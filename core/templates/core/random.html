Static reference · no database

InfraInv, drawn out.

InfraInv is an infrastructure inventory: a single place to record which organizations own which projects, where each project is deployed (dev, staging, UAT, production), the domains and servers behind those deployments, and the credentials needed to reach them. Secrets are encrypted at rest. This page documents the stack, layout, data model and request flow, and is rendered entirely from a template with no queries.

Tech stack

Pinned versions come from requirements.txt.

Backend

  • Django 5.2.10 — MVT framework
  • Django REST framework 3.16.1 — installed, API layer ready
  • django-environ 0.12.0 — 12-factor config from .env
  • django-cors-headers 4.9.0

Data

  • PostgreSQL via psycopg2-binary 2.9.11
  • SQLite for local dev (USE_SQLITE=TRUE)
  • django-taggit 6.1.0 — technology tags on servers
  • cryptography 49.0.0 — Fernet field encryption

Frontend

  • Django templates — server-rendered
  • Tailwind CSS (CDN) — pi.dev-inspired look
  • HTMX 2.0.10 + django-htmx 1.28.0 — partial swaps
  • Mermaid — diagrams on this page

Admin & tooling

  • django-jazzmin 3.0.2 — themed admin
  • django-debug-toolbar 6.2.0
  • Pillow 12.1.1 — image processing
  • Makefile — setup, migrate, test shortcuts

Auth

  • Custom user (users.CustomUser)
  • Email is the login identifier; no username
  • Session auth, LoginRequiredMixin
  • Superuser-only user management

Runtime

  • WSGI entrypoint, plus an ASGI entrypoint
  • Channels/Daphne: groundwork only, not yet enabled in INSTALLED_APPS
  • Python venv at ../.venv

core

The shared kernel. Holds the abstract BaseModel (soft-delete flag and timestamps), the Fernet-backed EncryptedTextField, the base layout and the dashboard views.

organizations

The inventory hierarchy: organization → project → deploy → domain → credential. Currently managed via admin; its URL conf is empty.

servers

Hosts that back a deploy: IP, port, region, provider, free-form notes, technology tags and an auto-deploy flag.

users

Email-based custom user with a role and an optional organization, plus superuser-gated user administration.

Runtime flows

Dashboard & HTMX project detail (sequence)

sequenceDiagram
    actor U as User
    participant B as Browser
    participant D as Django
    participant DB as Database
    U->>B: open /dashboard/
    B->>D: GET /dashboard/
    D->>D: LoginRequiredMixin check
    alt not authenticated
        D-->>B: 302 to /login/
    else authenticated
        D->>DB: Project.objects.all()
        DB-->>D: projects
        D-->>B: index.html with sidebar
    end
    U->>B: click a project
    B->>D: GET /detail/id/ (HTMX)
    D->>DB: Project select_related organization
    alt project missing
        D-->>B: redirect with error message
    else found
        D-->>B: partials/_detail.html fragment
        B->>B: HTMX swaps main content
    end

Credential encryption (sequence)

sequenceDiagram
    participant A as Admin / ORM
    participant F as EncryptedTextField
    participant K as Fernet key
    participant DB as Database
    A->>F: save(password="s3cret")
    F->>K: load FIELD_ENCRYPTION_KEY (or demo key)
    F->>DB: store Fernet token
    A->>F: read credential
    DB-->>F: Fernet token
    F->>K: decrypt
    F-->>A: "s3cret"

Setup & configuration

python3 -m venv ../.venv
source ../.venv/bin/activate
make setup      # install deps, create .env
# edit .env (USE_SQLITE=TRUE for local)
make migrate
python manage.py runserver

Environment variables

  • DEBUG, DJANGO_SECRET_KEY, ALLOWED_HOSTS
  • USE_SQLITE, or DB_ENGINE / NAME / USER / PASSWORD / HOST / PORT
  • CORS_ALLOW_ALL_ORIGINS, CSRF_TRUSTED_ORIGINS
  • FIELD_ENCRYPTION_KEY (optional; falls back to a demo key)
